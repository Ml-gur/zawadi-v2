# Zawadi (zawadi-v2) Security Audit — 2026-08-25

Scope: React 19 + Vite + Tailwind frontend · Supabase (PostgREST/RLS + Deno Edge Functions) · Vercel serverless `api/*` + `middleware.ts`.
Method: read-only code review of runtime code, migrations, git history (`git log --all`, full-history blob grep for secret values), `npm audit --omit=dev`. No production data or infrastructure was touched.

**Top 5 risks (priority order):**

1. **Payment sandbox bypass is env-var gated (FAIL-conditional, checks 32/63)** — In `supabase/functions/process-payment/index.ts` the default `ENVIRONMENT` is `development` (line 5–6). If `PAYSTACK_SECRET_KEY` is unset **or** `ENVIRONMENT≠production` in the deployed function secrets, any authenticated user can self-upgrade to Pro by calling `verify` with a reference prefixed `sandbox_` (lines 394–417) — no payment required.
2. **Privilege escalation via `profiles` INSERT (checks 34/51)** — Migration `001_initial_schema.sql:171-172` allows a user to INSERT their own profile row with *any* columns, including `role='super_admin'`, `plan='pro'`. Migration 013's trigger/policy guard only covers UPDATE. Exploitable whenever a profile row is missing while an auth user exists (e.g. after `admin-api` `user.delete` deletes the profile but fails to delete the auth user — admin-api/index.ts:249 logs exactly this failure mode and continues).
3. **Wildcard CORS on all sensitive Edge Functions (check 27)** — `admin-api:6`, `generate-essay:161`, `document-analysis:5`, `mentor-review:6`, `run-pipeline:6` all return `Access-Control-Allow-Origin: *`; `setup-admin:7` reflects arbitrary origins. Combined with service-role execution inside every function (blast radius of a single function bug ≈ full DB), least privilege is violated.
4. **AI spend abuse (checks 40/57/64)** — `api/ai-generate.js` is a general-purpose LLM proxy for any signed-in user (provider choice, 20k-char prompts, 4000 max_tokens) limited only by an in-memory per-instance counter that resets on cold start; `generate-essay:364` additionally lets the client override the LLM `model` string sent to paid provider APIs. No plan-tier daily quota applies to either path.
5. **Missing CSP + long-lived tokens in localStorage (checks 46/68)** — `vercel.json` ships HSTS/XFO/nosniff but no Content-Security-Policy; `src/lib/supabase.ts:7` uses supabase-js defaults, persisting access+refresh JWTs in localStorage. Any XSS becomes session-theft. (Related: `npm audit` reports 7 high prod-tree vulns incl. react-router open-redirect bypass.)

**Ship blockers (fix before launch):**

- [ ] Set `ENVIRONMENT=production` and ensure `PAYSTACK_SECRET_KEY` is present on the deployed `process-payment` function; delete or hard-gate the sandbox branch (verify with a `sandbox_`-prefix verify call → must return 402).
- [ ] Ship a migration extending the 013 privileged-column guard to INSERT (trigger on BEFORE INSERT, or WITH CHECK pinning `role='user' AND plan='explorer'` for non-service roles).
- [ ] Replace `*` CORS with an explicit production origin allowlist on all 7 Edge Functions.
- [ ] Remove the client-controlled `model`/`reqProvider` override in `generate-essay` and put a durable (DB-counted) daily/monthly quota on `api/ai-generate.js`.
- [ ] Add a restrictive `Content-Security-Policy`; move session storage to cookies (`@supabase/ssr`) or accept documented risk.
- [ ] Confirm production Supabase Auth settings: email confirmation ON, admin password ≠ placeholder, MFA (TOTP) enabled on super_admin.
